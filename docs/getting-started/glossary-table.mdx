:::info
This glossary defines key terms used throughout the documentation and expands on the [Glossary in the C2PA Content Credentials specification](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html#_glossary).
In case of a discrepancy, the C2PA specification takes precedence.
:::


<div className="glossary-table">

### A

<table>
  <thead>
    <tr>
      <th scope="col">Term</th>
      <th scope="col">Definition</th>
    </tr>
  </thead>
  <tbody>

    <tr>
      <th scope="row" id="action" style={{ verticalAlign: 'top', width: '25%' }}>Action</th>

<MarkdownCell valign="top">

An operation that an actor performs on an asset. For example, "create," "embed," or "change contrast" for an image. See [Assertions and actions](../manifest/writing/assertions-actions.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="active-manifest" style={{ verticalAlign: 'top', width: '25%' }}>Active manifest</th>

<MarkdownCell valign="top">

The last in the list of manifests inside of a manifest store. The active manifest has the set of content bindings that can be validated. See [Working with manifests](../manifest/understanding.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="actor" style={{ verticalAlign: 'top', width: '25%' }}>Actor</th>

<MarkdownCell valign="top">

A person, organization, device, or software product. For example, a camera, image editing software, cloud service, or the person using such tools.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="adobe-content-authenticity-aca" style={{ verticalAlign: 'top', width: '25%' }}>Adobe Content Authenticity (ACA)</th>

<MarkdownCell valign="top">

A [free web app](https://contentauthenticity.adobe.com/) that lets you apply, customize, and inspect Content Credentials and manage generative AI usage. For more information, see [Adobe Content Authenticity (Beta)](https://helpx.adobe.com/creative-cloud/apps/adobe-content-authenticity/beta-overview.html).  It includes **(ACA) Inspect**, a conforming validator product for viewing Content Credentials across various media types.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="archive" style={{ verticalAlign: 'top', width: '25%' }}>Archive</th>

<MarkdownCell valign="top">

The serialized, portable representation of a working store saved to a file or stream (typically a `.c2pa` file). An archive uses the standard JUMBF `application/c2pa` format and can be read back to restore a `Builder`. While "working store" emphasizes the editable state, "archive" emphasizes the saved bytes. See [Using working stores and archives](../tasks/archives.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="assertion" style={{ verticalAlign: 'top', width: '25%' }}>Assertion</th>

<MarkdownCell valign="top">

A data structure in the manifest that contains information about an asset's creation, authorship, how it's been edited, and other relevant information. For a list of standard assertions, see the [C2PA technical specification](https://c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html). See also [Assertions and actions](../manifest/writing/assertions-actions.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="asset" style={{ verticalAlign: 'top', width: '25%' }}>Asset</th>

<MarkdownCell valign="top">

A file or stream of data containing digital content. Currently, this means certain specific types of image, video, or audio files, but the types of supported assets will expand in the future. See also [composed asset](#composed-asset) and [derived asset](#derived-asset).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="asset-metadata" style={{ verticalAlign: 'top', width: '25%' }}>Asset metadata</th>

<MarkdownCell valign="top">

The portion of an asset that represents non-technical information about the asset and its digital content, as may be stored via standards such as Exif or XMP.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="asset-rendition" style={{ verticalAlign: 'top', width: '25%' }}>Asset rendition</th>

<MarkdownCell valign="top">

A representation of an asset (either as a part of an asset or a completely new asset) where the digital content has had a non-editorial transformation action (for example, re-encoding or scaling) applied but where the asset metadata has not been modified.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="authenticity" style={{ verticalAlign: 'top', width: '25%' }}>Authenticity</th>

<MarkdownCell valign="top">

A property of digital content comprising a set of facts (provenance data and hard bindings) that can be cryptographically verified as not having been tampered with.

</MarkdownCell>

    </tr>

  </tbody>
</table>

    <tr>
      <th scope="row" id="c2pa" style={{ verticalAlign: 'top', width: '25%' }}>C2PA</th>

<MarkdownCell valign="top">

See [Coalition for Content Provenance and Authenticity](#coalition-for-content-provenance-and-authenticity-c2pa).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="c2pa-conformance-program" style={{ verticalAlign: 'top', width: '25%' }}>C2PA conformance program</th>

<MarkdownCell valign="top">

C2PA program that provides assurance that products adhere to the Content Credentials specification, and fulfill a set of security requirements to ensure they are producing and validating C2PA data correctly. See [C2PA conformance program](../conformance/index.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="c2pa-tool" style={{ verticalAlign: 'top', width: '25%' }}>C2PA Tool</th>

<MarkdownCell valign="top">

Command-line utility for working with C2PA manifest data, implemented in the [c2pa-rs repository](https://github.com/contentauth/c2pa-rs). The name of the utility is "C2PA Tool," while the command to run the utility is `c2patool`. See [C2PA Tool documentation](../sdk-repos/c2patool/readme.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="c2pa-trust-list" style={{ verticalAlign: 'top', width: '25%' }}>C2PA trust list</th>

<MarkdownCell valign="top">

A C2PA-managed list of X.509 certificate trust anchors that issue certificates to hardware and software signers that use them to sign claims. See [Trust lists](../conformance/trust-lists.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="c2pa-tsa-trust-list" style={{ verticalAlign: 'top', width: '25%' }}>C2PA TSA trust list</th>

<MarkdownCell valign="top">

A C2PA-managed list of X.509 certificate trust anchors that issue certificates to time-stamp authorities (TSAs). See [Trust lists](../conformance/trust-lists.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="ca" style={{ verticalAlign: 'top', width: '25%' }}>CA</th>

<MarkdownCell valign="top">

See [Certificate authority](#certificate-authority-ca).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="cai" style={{ verticalAlign: 'top', width: '25%' }}>CAI</th>

<MarkdownCell valign="top">

See [Content AuthenticityInitiative](#content-authenticity-initiative-cai).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="cawg" style={{ verticalAlign: 'top', width: '25%' }}>CAWG</th>

<MarkdownCell valign="top">

See [Creator Assertions Working Group](#creator-assertions-working-group-cawg).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="cai-open-source-sdk" style={{ verticalAlign: 'top', width: '25%' }}>CAI open-source SDK</th>

<MarkdownCell valign="top">

Open-source software for developing Content Credentials applications; includes the C2PA Tool, Rust library, and libraries for Python, C/C++, web JavaScript, Node.js, Android, and iOS. See [Introduction](../introduction.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="cbor" style={{ verticalAlign: 'top', width: '25%' }}>CBOR</th>

<MarkdownCell valign="top">

See [Concise Binary Object Representation](#concise-binary-object-representation-cbor).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="certificate" style={{ verticalAlign: 'top', width: '25%' }}>Certificate</th>

<MarkdownCell valign="top">

An electronic document (also called a public key certificate or digital certificate) that vouches for the holder's identity. Like a passport, the certificate is issued by a trusted third party (the certificate authority or CA), cannot be forged, and contains identifying information. See [Signing and certificates](../signing/index.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="certificate-authority-ca" style={{ verticalAlign: 'top', width: '25%' }}>Certificate authority (CA)</th>

<MarkdownCell valign="top">

A trusted third party that verifies the identity of an organization applying for a digital certificate. After verifying the organization's identity, the CA issues a certificate and binds the organization's identity to a public key. A digital certificate can be trusted because it is chained to the CA's root certificate. See [Getting a certificate](../signing/get-cert.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="claim" style={{ verticalAlign: 'top', width: '25%' }}>Claim</th>

<MarkdownCell valign="top">

Digitally signed and tamper-evident data in a manifest that references a set of assertions by one or more actors, concerning an asset, and the information necessary to represent the content binding. For example, a claim could specify that a particular image was edited by John Doe using Product X on 05/08/2021 at 11am to change the image contrast.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="claim-generator" style={{ verticalAlign: 'top', width: '25%' }}>Claim generator</th>

<MarkdownCell valign="top">

The non-human (hardware or software) actor that generates the claim about an asset as well as the claim signature, thus leading to the asset's associated manifest.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="claim-signature" style={{ verticalAlign: 'top', width: '25%' }}>Claim signature</th>

<MarkdownCell valign="top">

Part of the manifest that is the digital signature on the claim using an actor's private key. See [Signing and certificates](../signing/index.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="coalition-for-content-provenance-and-authenticity-c2pa" style={{ verticalAlign: 'top', width: '25%' }}>Coalition for Content Provenance and Authenticity (C2PA)</th>

<MarkdownCell valign="top">

A formal coalition that drafts technical standards and specifications as a foundation for universal content provenance. The C2PA is a mutually governed standards development organization (SDO) under the structure of the Linux Foundation's Joint Development Foundation. For more information, see [c2pa.org](https://c2pa.org).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="composed-asset" style={{ verticalAlign: 'top', width: '25%' }}>Composed asset</th>

<MarkdownCell valign="top">

An asset created from multiple parts or fragments of digital content (referred to as ingredients). For example, an image (image A) with another image (image B) imported and superimposed on top of it. In this example, image B is referred to as an ingredient. When starting from an existing asset, it's a special case of a derived asset; however, a composed asset can also be created from a "blank slate."

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="conformance" style={{ verticalAlign: 'top', width: '25%' }}>Conformance</th>

<MarkdownCell valign="top">

See [C2PA conformance program](#c2pa-conformance-program).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="conforming-product" style={{ verticalAlign: 'top', width: '25%' }}>Conforming product</th>

<MarkdownCell valign="top">

A product that has been approved by C2PA as part of the [C2PA conformance](#c2pa-conformance-program); either a [validator product](#validator-product) that inspects and validates Content Credentials, a [generator product](#generator-product) that creates and signs Content Credentials, or a certificate authority that issues claim-signing certificates for use by generator products.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="concise-binary-object-representation-cbor" style={{ verticalAlign: 'top', width: '25%' }}>Concise Binary Object Representation (CBOR)</th>

<MarkdownCell valign="top">

A binary data serialization format loosely based on JSON that allows the transmission of data objects containing name-value pairs, but in a more concise manner than with JSON. CBOR is defined in Internet Standard [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="content-authenticity-initiative-cai" style={{ verticalAlign: 'top', width: '25%' }}>Content Authenticity Initiative (CAI)</th>

<MarkdownCell valign="top">

A group of creators, technologists, journalists, and activists leading the global effort to address digital misinformation and content authenticity. Collaborators include: Adobe, BBC, Microsoft, The New York Times Co., Leica, Nikon, Truepic, and Qualcomm. For more information, see [Content Authenticity Initiative](https://contentauthenticity.org).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="content-binding" style={{ verticalAlign: 'top', width: '25%' }}>Content binding</th>

<MarkdownCell valign="top">

Information that associates specific digital content to a specific manifest associated with a specific asset, either as a hard binding or a soft binding. See [Working with manifests](../manifest/understanding.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="content-credentials" style={{ verticalAlign: 'top', width: '25%' }}>Content Credentials</th>

<MarkdownCell valign="top">

Tamper-evident metadata associated with an asset that shows the attribution and provenance details for an asset. Corresponds to a manifest store. See [Working with manifests](../manifest/understanding.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="context" style={{ verticalAlign: 'top', width: '25%' }}>Context</th>

<MarkdownCell valign="top">

A class in the SDK that comprises Settings and optionally a Signer, and that you pass to Reader or Builder to control their behavior. See [Configuring SDK settings with Context](../tasks/settings.mdx) and [Settings reference](../manifest/json-ref/settings-ref.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="contextprovider" style={{ verticalAlign: 'top', width: '25%' }}>ContextProvider</th>

<MarkdownCell valign="top">

An abstract base class in the SDK that defines the interface Reader and Builder use to access a context.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="creator-assertions-working-group-cawg" style={{ verticalAlign: 'top', width: '25%' }}>Creator Assertions Working Group (CAWG)</th>

<MarkdownCell valign="top">

A working group within the Decentralized Identity Foundation (DIF) that defines technical standards for:

- [Identity assertions](#identity-assertion), proving who created content.
- Metadata assertions, providing detailed information about content.
- Training and data mining assertions, specifying how content may be used. 

For details, see the [CAWG website](https://cawg.io/)

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="cryptographic-hash" style={{ verticalAlign: 'top', width: '25%' }}>Cryptographic hash</th>

<MarkdownCell valign="top">

An algorithm that can be run on digital data such as an image file to produce a unique "fingerprint" value. If the data changes then the hash value will also change.

</MarkdownCell>

    </tr>

  </tbody>
</table>

<MarkdownCell valign="top">

A fingerprint stored in a watermarked image’s manifest, checked against the queried image to prevent watermark spoofing.

    <tr>
      <th scope="row" id="derived-asset" style={{ verticalAlign: 'top', width: '25%' }}>Derived asset</th>

<MarkdownCell valign="top">

An asset created by starting from an existing asset and performing actions on it that modify its digital content and asset metadata.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="digital-content" style={{ verticalAlign: 'top', width: '25%' }}>Digital content</th>

<MarkdownCell valign="top">

The portion of an asset that represents the actual content, such as the pixels of an image, along with any additional technical metadata required to understand the content (for example, a color profile or encoding parameters).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="durable-content-credentials" style={{ verticalAlign: 'top', width: '25%' }}>Durable Content Credentials</th>

<MarkdownCell valign="top">

An approach to help content provenance persist across content platforms by using C2PA manifest data in conjunction with invisible watermarks, actively inserted into the content, and content fingerprints, passively computed from the content. See [Durable Content Credentials](../durable-cr/index.md).

</MarkdownCell>

    </tr>

### I

    <tr>
      <th scope="row" id="identity-assertion" style={{ verticalAlign: 'top', width: '25%' }}>Identity assertion</th>

<MarkdownCell valign="top">

A CAWG assertion that enables a credential holder to prove control over a digital identity and to use that identity to document the named actor's role(s) in an asset's lifecycle. See [CAWG - Identity Assertion](https://cawg.io/identity/) and [Reading CAWG identity assertions](../manifest/reading/reading-cawg-id.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="identity-claims-aggregator" style={{ verticalAlign: 'top', width: '25%' }}>Identity claims aggregator (ICA)</th>

<MarkdownCell valign="top">

An actor that collects CAWG identity claims (attestations) regarding a named actor from various identity providers and can replay those identity claims into identity assertions on behalf of the named actor. This may be the same as the identity assertion generator.

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="ingredient" style={{ verticalAlign: 'top', width: '25%' }}>Ingredient</th>

<MarkdownCell valign="top">

Part of a composed asset, such as an image superimposed on top of another image. See [Reading ingredients](../manifest/reading/ingredients-reading.md) and [Writing ingredients](../manifest/writing/ingredients.md).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="intent" style={{ verticalAlign: 'top', width: '25%' }}>Intent</th>

<MarkdownCell valign="top">

A declaration that tells a `Builder` what kind of manifest to create. Intents enable validation, add actions required by the C2PA specification, and help prevent invalid operations. There are three intent types: **Create** for new digital creations (requires a `DigitalSourceType` and must not have a parent ingredient), **Edit** for modifying a pre-existing parent asset (must have a parent ingredient), and **Update** for non-editorial changes such as re-encoding (a restricted version of Edit). See [Using builder intents](../tasks/intents.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="interim-trust-list" style={{ verticalAlign: 'top', width: '25%' }}>Interim trust list</th>

<MarkdownCell valign="top">

Initial Content Authenticity trust list that was frozen as of 1 Jan 2026. See [Trust lists](../conformance/trust-lists.mdx).

</MarkdownCell>

    </tr>

    <tr>
      <th scope="row" id="invisible-watermark" style={{ verticalAlign: 'top', width: '25%' }}>Invisible watermark</th>

<MarkdownCell valign="top">

See [watermark](#watermark).

</MarkdownCell>

    <tr>

    <tr>

<MarkdownCell valign="top">

In public key cryptography, a unique digital key (very long number) used to encode messages that can then be decrypted with the corresponding private key. Every public key matches to exactly one private key. A message encoded using a particular public key can be decoded only by using the matching private key.
