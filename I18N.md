# Internationalization plan

## Scope

English remains the source language and keeps its existing URLs. Launch French
(`fr`), Italian (`it`), German (`de`), and Spanish (`es`) under locale prefixes.
Translate Introduction, Getting Started, FAQs, and Glossary in each language.
Keep all other documents accessible in English, with a localized notice.
Fetched SDK documentation and generated API references remain English initially.

## Locale infrastructure

- Configure Docusaurus locales and native language names.
- Add the language dropdown without automatic browser-language redirection.
- Preserve the locale in homepage, documentation, and legacy SDK redirects.
- Extract and translate UI catalogs, navigation, accessibility labels, and footer
  text. Translation extraction does not translate Markdown documents.
- Detect English fallback from document source metadata. Show a localized notice
  and mark the English document body with `lang="en"`.
- Keep English fallback edit links pointed at their English sources. Point
  translated document edit links at the localized files.

## Manual translation pilot

- Mirror English paths under
  `i18n/<locale>/docusaurus-plugin-content-docs/current/`.
- Translate these four documents in each language:
  - [Introduction](docs/introduction.mdx)
  - [Getting Started](docs/getting-started/index.mdx)
  - [FAQs](docs/getting-started/faqs.mdx)
  - [Glossary](docs/getting-started/glossary.mdx)
- Preserve IDs, slugs, stable heading anchors, MDX imports, JSX, code, placeholders,
  and links. Translate titles, prose, descriptions, and alternative text.
- Establish a terminology glossary and a human reviewer for each locale.
- Track the English source hash for each translation and flag changes for review.
  Never silently overwrite translations when English changes.
- Identify images with English text and either localize them or explicitly accept
  them for the pilot.
- Use the shared `SdkOverview` component for the diagram in translated Introduction
  pages. Its live text uses `site.sdkOverview.*` entries in each locale's
  `code.json`; translate every label when adding a locale. Preserve package names,
  platform names, and the Adobe Content Credentials Cloud product name. The diagram
  scrolls horizontally on narrow screens instead of shrinking its text. Keep the
  English raster and the `cr` trademark icon unchanged. Diagrams and screenshots
  on English fallback pages remain outside this localization scope.
- Keep translations separate from the remote documentation fetch process.

## Publishing and quality gates

- Verify localized normal and 404 navigation, search, edit links, and redirects.
- Confirm the production origin before changing canonical URLs. The configuration
  currently uses `https://contentauth.netlify.com`; the README identifies
  `https://opensource.contentauthenticity.org/` as the public site.
- Check canonical URLs, sitemap entries, and `hreflang`. Exclude English fallback
  copies from indexing rather than treating them as translated documents.
- Configure the existing Algolia crawler and language facets for locale routes.
- Confirm Netlify builds and publishes all five locales, including PR previews.
- Review broken-link warnings explicitly because the current build does not fail
  on them.

## TMS integration

After the manual pilot works, select a translation management system (TMS) that
supports Docusaurus JSON catalogs and preserves MDX syntax. Test representative
files before selecting a vendor. Initially sync only approved pilot documents
and UI catalogs. Import translations through reviewed pull requests, not direct
production updates.

Protect technical terms and immutable fields. Use terminology, translation
memory, and English source hashes to request only necessary updates. Keep TMS
credentials in CI secrets, use HTTPS and least-privilege permissions, and validate
returned files before building. No TMS credentials or integration are needed for
the manual pilot.

## Additional languages

Add languages through the same file-based workflow. Before introducing Asian
languages, decide regional locale identifiers and verify font coverage, wrapping,
search tokenization, and reviewer availability. Treat regional variants and
right-to-left languages as explicit decisions rather than implicit defaults.
